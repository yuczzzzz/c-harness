Chrome Manifest V3 extension

c-harness

让网页版大模型在 Chat 模式中，按需读取你主动导入的 Skill 与 Reference， 并在确认后调用你添加的 MCP 服务。

Why c-harness

把能力带进对话，不打断对话

不必反复复制 Skill 正文、Reference 或工具结果。c-harness 用可见、固定的 Harness 约定，让模型明确请求它此刻真正需要的内容。

Capabilities

两类能力，一条清晰边界

01 Skill

按需披露本地说明

从 ZIP 导入包含 SKILL.md 和可选 references/ 的 Skill 包。 对话开始只发送 Skill 目录，正文由模型通过显式命令按需读取。

  • 本地导入、搜索、覆盖与删除
  • Skill 与 Reference 分阶段读取
  • 可全局停用，不删除已有内容
02 MCP

经确认调用外部工具

添加无鉴权 Streamable HTTP MCP 服务。模型先读取服务详情，再按 Tool 名称和结构化参数请求调用； 默认每次调用都由用户确认。

  • 服务目录与 Tool 详情渐进披露
  • 支持当前目标网站会话内信任
  • 优先回填 structuredContent
03 Timing

模拟真人回复间隔的自动回注延迟

可配置 1–60 秒的最小值与最大值。扩展在每次适用的自动回注前独立随机抽样一个整数秒， 模拟更接近真人操作的回复间隔；首次 Harness 和 MCP 确认后的反馈不延迟，等待期间也可随任务取消。

Workflow

从问题到最终回答

每条用户消息发起一个临时增强任务。扩展只解析正文为严格 YAML mapping 的显式围栏命令， 不从自然语言猜测工具意图。

  1. 01

    发送 Harness

    附带固定协作约定、能力目录和用户原始问题。

  2. 02

    按需读取

    模型通过 skill、read 或 mcp 请求必要内容。

  3. 03

    确认调用

    mcp-call 默认弹出确认；可信服务可在当前目标网站会话内免重复确认。

  4. 04

    形成最终回答

    扩展回注真实内容与结果，模型继续对话，直到回复中不再包含已识别命令。

MCP call control

每次工具调用，都由你决定

模型只有在读取服务详情后才能请求调用 MCP Tool。服务尚未获得当前会话信任时， c-harness 会在页面上展示调用服务、Tool 名称和完整参数，等待你明确选择。

仅本次允许
只执行当前这一次调用，下次仍需确认。
信任当前会话并允许
服务详情未变化时，当前目标网站会话不再重复确认。
拒绝
不调用 Tool，并将拒绝结果反馈给模型继续处理。

能力边界

本地开发环境能力来自 MCP

c-harness 只负责网页版大模型 Chat 模式与 Skill、MCP 之间的 Agent Loop。 本地文件读写、命令行执行和项目构建等能力由用户添加的 MCP 提供，调用前仍遵循扩展的确认与信任规则。

Scope

专注网页对话模型的 Agent Loop

当前支持

  • Chrome 桌面版 114 及以上
  • DeepSeek 与 Z.ai Chat 模式
  • 文本 Skill、Reference 与无鉴权 MCP
  • 普通模式和深度思考模式的最终回答区域

当前不支持

  • 其他浏览器、其他网站或 Z.ai Agent 模式
  • 扩展直接读写任意本地目录、执行命令行工具、脚本或项目构建
  • 任务恢复、多智能体或通用知识库

Download & install

下载并安装 c-harness

当前通过 GitHub Releases 提供适用于 Chrome 114 及以上版本的扩展安装包。

  1. 前往 Releases 页面，下载最新版本的 c-harness-*-chrome.zip。
  2. 将 ZIP 完整解压到一个固定目录。
  3. 打开 chrome://extensions，开启右上角的“开发者模式”。
  4. 点击“加载已解压的扩展程序”，选择刚才解压的目录。
前往 Releases 下载

从源码构建

需要 Node.js 22.18.0 及以上、23 以下版本，以及 pnpm 11.10.0。

$ git clone https://github.com/yuczzzzz/c-harness.git
$ cd c-harness
$ pnpm install
$ pnpm build

构建完成后，在扩展管理页加载 .output/chrome-mv3 目录。
