Quick start

快速开始

先把 c-harness 安装到 Chrome，再启动一个本地开发环境 MCP。完成后，DeepSeek 或 Z.ai 就能在你的确认下读取、编辑工作区文件并运行受限开发命令。

  1. 01安装扩展
  2. 02准备 Node.js
  3. 03初始化本地开发环境 MCP
  4. 04连接 MCP
01

Install extension

安装 c-harness

  1. 下载扩展安装包

    前往 GitHub Releases， 下载最新版本的 c-harness-*-chrome.zip，然后把 ZIP 完整解压到一个固定目录。

  2. 打开 Chrome 扩展管理页

    在地址栏输入 chrome://extensions，打开页面右上角的“开发者模式”。

  3. 加载已解压的扩展

    点击“加载已解压的扩展程序”，选择刚才解压的目录。安装后可从扩展详情页进入“扩展程序选项”。

Chrome 不能直接加载下载的 ZIP。升级时请下载新版本、解压到固定目录，再回到扩展管理页重新加载。
02

Local environment

准备本地开发环境

c-harness 本身不会直接访问本地文件或执行命令。这里以 CodexPro 为例：它把你明确选择的工作区作为 MCP 服务开放给扩展。CodexPro 要求 Node.js 20 或更高版本。

macOS

使用 nvm 安装并管理 Node.js，避免把 Node 版本绑定到系统环境。

  1. 按照 nvm 官方安装说明 安装 nvm，然后重新打开终端。
  2. 安装并切换到 Node.js 20：
$ nvm install 20
$ nvm use 20
$ node --version
$ npm --version

Windows

先准备 Git Bash，再通过 nvm-windows 安装 Node.js。后续 CodexPro 命令全部在 Git Bash 中执行。

  1. 从 Git for Windows 下载并安装，保留 Git Bash 组件。
  2. 从 nvm-windows Releases 下载最新安装程序。若电脑已有独立安装的 Node.js，请先按项目说明处理旧版本，避免 PATH 冲突。
  3. 打开 Git Bash，安装并切换到 Node.js 20：
$ nvm install 20
$ nvm use 20
$ node --version
$ npm --version
从这一步开始，请始终使用 Git Bash 启动和操作 CodexPro。
03

CodexPro

初始化工作区并启动 MCP

  1. 安装 CodexPro

    $ npm install -g codexpro
$ codexpro --version

  2. 在自定义工作区目录中初始化

    把示例路径替换成你允许网页模型访问的项目目录。Windows 用户继续在 Git Bash 中使用正斜杠路径。

    macOS 
    $ cd /Users/your-name/code/my-project
$ codexpro setup --tunnel none --no-auth
    Windows · Git Bash 
    $ cd /c/Users/your-name/code/my-project
$ codexpro setup --tunnel none --no-auth

    命令会把当前目录保存为工作区，并明确使用仅绑定本机回环地址的无鉴权本地模式。

    默认键入 Enter 选择推荐配置即可。

  3. 以本地模式启动

    以后只需进入同一工作区并运行：

    $ codexpro start --tunnel none --no-auth

    保持这个终端窗口运行。默认的无鉴权 Streamable HTTP 地址为：

    http://127.0.0.1:8787/mcp
只授权可信目录

CodexPro 的 Tool 可以读取、修改文件并运行受限命令。请仅把你愿意开放的项目设为工作区，并在 c-harness 弹出调用确认时检查 Tool 与参数。

04

Connect MCP

把 CodexPro 添加到扩展

  1. 打开 MCP 管理

    进入 c-harness 的“扩展程序选项”，在左侧选择“MCP 管理”。

  2. 添加服务地址

    在“添加 MCP 服务”中粘贴 http://127.0.0.1:8787/mcp，点击“添加”。该地址使用 Streamable HTTP，无需填写鉴权信息。

  3. 确认本地环境识别

    c-harness 会读取 MCP 初始化信息中的 serverName，以忽略大小写的精确匹配识别 CodexPro，而不是根据服务地址或服务 ID 推断。识别成功后，模型在文件、本地、工作区、文件目录和本地 Skill 场景会收到使用 CodexPro 的提示。

    若同时连接了多个被识别为 CodexPro 的服务，Harness 会优先选择 serverTitle 排序最靠前的一项；没有标题的服务排在后面，同标题再按 serviceId 排序。MCP 管理页会列出所有命中服务和当前选择。

  4. 开始网页对话

    打开 DeepSeek 或 Z.ai 的 Chat 模式正常提问。模型需要本地能力时会先读取 CodexPro 详情，再请求调用具体 Tool；检查参数后选择仅本次允许、信任当前会话并允许或拒绝。若同时启用了 Skill，模型会先向你确认 Skill 来源，确认前不会发出 Harness 命令。

Ready

网页对话已经接入本地工作区

现在可以让模型检查项目、读取或修改文件，并运行 CodexPro 允许的验证命令。所有实际能力都来自 CodexPro，c-harness 负责协调请求、回注结果和调用确认；启用 Skill 时会先由你确认其来源。
